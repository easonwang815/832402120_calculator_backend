## 一、核心功能（硬性要求，共 4 项）

| # | 功能 | 拆解要求 | 验收标准 | 对应评分 |
|---|---|---|---|---|
| F1 | 基础四则运算 | 支持 `+` `-` `×` `÷` | 前端输入 `12+8` → 后端返回 20 → 前端展示后端返回的结果 | 后端基础计算 15' |
| F2 | 复合表达式 | 运算符优先级、括号、一元正负、小数、无效表达式、除零 | `1+2*3=7`、`(1+2)*3=9`、`10/2+7=12`、`8-3*2=2`、`-5+8=3`、`3*-2=-6`、`2.5*4=10`；`1+*2` / `abc` 报"无效表达式"；`10/0` 报"除零错误" | 后端复合表达式 15' |
| F3 | 计算历史 | 每次**成功**计算存入后端数据库（表达式、结果、时间） | 前端能拉取并展示历史；**刷新、重启、重开前端历史不丢失**（数据在后端库） | 后端历史 10' |
| F4 | 删除历史 | 按 id 删除指定记录；可加"清空全部" | 删除请求走后端 API，**数据库真实删除**；删除后前端重新拉取最新历史 | 后端删除历史 10' |

## 二、架构与工程要求

| # | 要求 | 说明 |
|---|---|---|
| A1 | 前后端分离 | 核心计算必须由后端完成；前端只发表达式、显示后端返回结果。**自检方法**：停掉后端服务，前端应无法独立得出新计算结果 |
| A2 | 禁止 eval 类执行 | 不可以用 `ScriptEngine` 等执行用户输入的任意代码；自己实现解析器（词法分析 + 调度场/后缀表达式），或使用安全解析库并在博客说明 |
| A3 | API + JSON | 接口职责清晰、响应格式统一、合理 HTTP 状态码（200 / 400 / 404 / 500 等） |
| A4 | 双仓库 | 前端、后端**两个独立 GitHub 仓库**，各含 `README.md` 和 `codestyle.md`（开头注明标准来源，Java 用 Google Java Style Guide） |
| A5 | 数据库持久化 | MySQL 存储历史；不得依赖前端缓存 / LocalStorage / 内存 |
| A6 | 部署 | 评审期内提供**可公开访问**的项目地址；后端服务保持可访问 |

## 三、加分项（0~10'，可选）

> 附加功能必须**真实可用**，并在博客中详细描述和演示。仅加界面元素不算。

可选方向：科学计算、进制转换、单位转换、历史搜索/分页、用户账号与独立历史、收藏记录、键盘快捷键、主题切换、计算统计等。

**本项目已实现的加分项**：
- 键盘快捷键与一键清空历史
- 历史记录按表达式/结果搜索，并由后端数据库分页
- 科学计算：次方、开方、角度制三角函数
- 2 / 8 / 10 / 16 进制整数互转
