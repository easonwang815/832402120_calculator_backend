# 05 · 系统架构与目录结构

> 技术栈：后端 Spring Boot 3（Java 17）+ MySQL ｜ 前端原生 HTML/CSS/JS（可选 Vue）
> 架构模式：前后端分离，HTTP + JSON 通信

## 一、总体架构

```
┌─────────────────┐     HTTP/JSON      ┌──────────────────┐      JDBC      ┌──────────┐
│  前端 (Web)      │ ─────────────────► │  后端 Spring Boot │ ──────────────► │  MySQL   │
│  HTML/CSS/JS    │ ◄───────────────── │  分层架构         │ ◄────────────── │ 数据库   │
└─────────────────┘    JSON 响应       └──────────────────┘                 └──────────┘
```

**职责边界**：
- 前端：界面呈现、按钮交互、表达式输入、发送请求、显示结果/历史/错误信息
- 后端：接收请求、输入校验、表达式解析与计算、异常处理、历史存取、统一响应
- **核心计算只发生在后端**；前端永远不计算结果

**架构合规自检**：停止后端服务后，前端仍可输入和交互，但无法得到任何新的有效计算结果。

## 三、表达式计算模块设计（核心难点）

采用 **Token 化（词法分析）+ 调度场算法（Shunting-yard）+ 数值栈求值**：

1. **词法分析（ExpressionParser）**：把 `"(1+2)*-3"` 拆成 Token 序列
   - `(` `1` `+` `2` `)` `*` `-` `3`
   - 处理一元正负号：`-3` 开头的 `-` 标记为"一元负号"，`3*-2` 中 `*` 后的 `-` 同样处理
2. **语法分析 + 求值（ExpressionEvaluator）**：
   - 用调度场算法把中缀表达式转成后缀（逆波兰）表达式，天然解决**运算符优先级**和**括号**
   - 后缀表达式用栈求值；一元负号在遇到时对栈顶取负
   - 数字用 `BigDecimal` 计算，除法保留 10 位小数（四舍五入），避免精度问题
3. **异常处理（CalculatorException）**：
   - 非法字符、括号不匹配、缺少操作数、非法运算符组合、表达式为空 → 无效表达式
   - 除数为零 → 除零错误
   - 所有异常由 Controller 统一转为 400 响应

> **为什么不用 `ScriptEngine` / `eval`**：作业明确禁止执行用户输入的任意代码（安全风险）。调度场算法只做数学运算，不执行任何代码，安全且完全可控，博客里可以重点讲这个模块。

## 四、前端目录结构

```
calculator_frontend/
├── index.html              # 计算器界面：数字/运算符按钮、表达式输入框、结果区、历史列表
├── css/
│   └── style.css           # 样式（清晰简洁即可，不追求过度视觉效果）
├── js/
│   ├── api.js              # 封装 fetch：calculate(expr) / getHistory() / deleteHistory(id)
│   └── app.js              # 交互逻辑：按钮输入、发起请求、渲染结果/历史、错误提示
├── README.md
└── codestyle.md
```

前端要点：
- 界面展示 `×` `÷`，发送给后端时转换为 `*` `/`（作业允许）
- 错误提示区：展示后端返回的 `message`（如"无效表达式""除零错误"）
- 历史列表：页面加载时调用 GET /api/history 渲染；删除按钮调用 DELETE 后重新拉取

## 五、技术选型理由（供博客使用）

| 选择 | 理由 |
|---|---|
| Spring Boot | 主流、分层清晰（Controller/Service/Repository），贴合课程软件工程规范；生态成熟 |
| MySQL | 作业示例数据库之一；主流关系型数据库，博客好讲解；支持真正的持久化 |
| 原生 HTML/JS 前端 | 无构建步骤、依赖少，评审/部署最简单；前端职责（交互与展示）被最大程度突显 |
| 调度场算法 | 不依赖第三方库、可完整讲解表达式解析原理，同时满足"禁止 eval"要求 |
