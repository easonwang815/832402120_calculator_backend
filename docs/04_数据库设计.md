# 04 · 数据库设计

> 数据库：MySQL ｜ 用途：持久化计算历史记录
> 作业要求历史数据在后端数据库持久化，刷新/重启前端不丢失。

## 一、表结构

### calculation_history（计算历史表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | BIGINT | PRIMARY KEY, AUTO_INCREMENT | 主键，自增 |
| expression | VARCHAR(255) | NOT NULL | 表达式原文，如 `(1+2)*3` |
| result | VARCHAR(1024) | NOT NULL | 计算结果（字符串），如 `9`、`-6`、`0.3333333333` |
| created_at | DATETIME(6) | NOT NULL | 计算时间，由后端保存实体前写入 |

## 二、建表 SQL

```sql
CREATE TABLE calculation_history (
    id          BIGINT       NOT NULL AUTO_INCREMENT,
    expression  VARCHAR(255) NOT NULL,
    result      VARCHAR(1024) NOT NULL,
    created_at  DATETIME(6)   NOT NULL,
    PRIMARY KEY (id),
    KEY idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

说明：
- `idx_created_at` 索引加速"按时间倒序查询历史"（GET /api/history 高频使用）。
- `utf8mb4` 字符集，兼容各种符号输入。

## 三、字段设计思路（供博客使用）

1. **`result` 为什么用 VARCHAR 而不用 DECIMAL/DOUBLE**
   - 除法结果可能是无限循环小数（如 `1/3`），若直接存 DOUBLE 会丢失精度且存储值不直观；
   - 后端计算统一使用 `BigDecimal`，除法保留 10 位小数（四舍五入）后格式化为字符串存储，展示即所见；
   - 字符串对前端 JSON 解析最安全，不出现 `0.30000000000000004` 这类浮点噪声。

2. **`expression` 存原文而非计算过程**
   - 历史记录需要完整还原用户输入（如 `3*-2`），方便回看和后续加分项（搜索、统计）。

3. **`created_at` 由后端统一生成**
   - 实体通过 `@PrePersist` 在保存前写入 `LocalDateTime.now()`，兼容 H2 和 MySQL。

## 四、JPA 实体映射（Java）

```java
@Entity
@Table(name = "calculation_history")
public class CalculationHistory {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 255)
    private String expression;

    @Column(nullable = false, length = 1024)
    private String result;

    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    @PrePersist
    void onCreate() {
        this.createdAt = LocalDateTime.now();
    }
}
```

> 说明：时间由同一后端进程生成；部署时应固定服务器时区，避免展示偏差。

## 五、初始化方式

- 开发环境：`spring.jpa.hibernate.ddl-auto=update`（自动建表，省事）
- 部署环境：运行 `schema-mysql.sql` 初始化表，并使用 `ddl-auto=validate` 校验结构，避免意外变更
